# 📦 Requirements Deep-Dive

This document explains why we have chosen specific libraries for the High-Assurance API. We follow a "Minimalist & Secure" philosophy—every dependency must earn its place.

---

## 1. Security & Cryptography
### `pyseto`
- **Purpose**: Implementation of PASETO (Platform-Agnostic Security Tokens).
- **Rationale**: We chose this over `PyJWT` to eliminate algorithm-confusion vulnerabilities. `pyseto` provides a modern, opinionated API for v4 tokens.

### `cryptography`
- **Purpose**: Core cryptographic primitives (Ed25519).
- **Rationale**: The industry-standard library for Python. It provides the low-level bindings used by `pyseto` for signing and verification.

### `fido2`
- **Purpose**: FIDO2 / WebAuthn implementation.
- **Rationale**: Enables phishing-resistant multi-factor authentication. Used in `src/auth.py` for future-proof identity verification.

---

## 2. Infrastructure & Communication
### `grpcio` & `protobuf`
- **Purpose**: High-speed internal communication and audit streaming.
- **Rationale**: gRPC is faster than REST for internal service-to-service calls. Protobuf ensures a strict, type-safe contract for our audit logs.

### `flask` & `gunicorn`
- **Purpose**: REST API framework and production WSGI server.
- **Rationale**: Flask is minimal and highly extensible. Gunicorn provides the multi-threaded stability required for production loads.

### `opentelemetry-api` & `opentelemetry-sdk`
- **Purpose**: Distributed tracing and observability.
- **Rationale**: Allows us to track requests across services using a vendor-neutral standard. Essential for debugging in microservice environments.

---

## 3. Testing & Validation
### `pytest` & `pytest-cov`
- **Purpose**: Testing framework and coverage enforcement.
- **Rationale**: Pytest is the gold standard for Python testing. `pytest-cov` is used to enforce our 100.0% coverage requirement.

### `schemathesis`
- **Purpose**: Property-based API fuzzing.
- **Rationale**: Automatically generates hundreds of test cases based on our `openapi.yaml` to find edge-case 500 errors.

### `pytest-benchmark`
- **Purpose**: Latency and performance verification.
- **Rationale**: Ensures that new code does not introduce algorithmic regressions (e.g., O(n^2) complexity in transfer logic).

---

## 4. Static Analysis (Compliance)
### `ruff`
- **Purpose**: Ultra-fast linter and Cyclomatic Complexity gate.
- **Rationale**: Replaces multiple tools (flake8, isort, black) while being 10-100x faster.

### `flake8-cognitive-complexity`
- **Purpose**: Measuring "understandability" of the code.
- **Rationale**: Complements cyclomatic complexity by penalizing deep nesting, which is a major source of human error.

### `cyclonedx-bom`
- **Purpose**: SBOM (Software Bill of Materials) generation.
- **Rationale**: Required for modern supply chain security compliance (Executive Order 14028).
